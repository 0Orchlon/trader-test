Download OpenAPI specification:

Ганц operator-т зориулсан арилжааны системийн REST API.

Бүх хариунд хүчинтэй гурван үл хөдлөх дүрэм:

  1. Мөнгөн утга бүр тэмдэгт мөр хэлбэрийн fixed-point decimal ("10234.56"). Float ХЭЗЭЭ Ч биш (AC-25).
  2. Timestamp бүр UTC, RFC 3339, Z төгсгөлтэй (AC-26).
  3. Өгөгдөлтэй хариу бүр source талбартай ба нэг хариу дотор ХОЛИМОГ source байхыг хориглоно (AC-20, AC-21).

Аюулгүйн гэрээ: энэ API-д Alpaca руу order илгээх ЦОРЫН ГАНЦ зам нь POST /orders/manual ба approval queue-ийн approve хоёр. Хоёул дотооддоо Risk Agent → Execution модулиар дамжина. LLM нь энэ API-д огт хүрэхгүй — LLM зөвхөн Tool Contract (энэ файлын 3-р баримт) руу ханддаг.

AC-1: талбар бүр Alpaca REST-ийн хариунаас ШУУД гарна. Backend нь equity, buying power зэргийг локалаар ХЭЗЭЭ Ч дахин тооцохгүй.

Operator-ийн гараар илгээх order (FR-12, AC-31…AC-33)

Agent-ийн order-той ЯГ ИЖИЛ зам: Risk Agent → Execution → Alpaca. Тусдаа, хаалтгүй зам БАЙХГҮЙ.

Төлөвийн хараат байдал (AC-33):

  • halted → 409 system_halted, Alpaca руу 0 дуудалт.
  • winding_down → зөвхөн эрсдэл БАГАСГАХ order; нэмэгдүүлэх нь 422 winding_down_increase_blocked.
  • active → Risk-ийн ердийн шалгалт.

Хоёр шаттай баталгаажуулалт: Risk ESCALATE_TO_HUMAN буцаавал (жишээ нь notional > MAX_ORDER_NOTIONAL) backend нь 409 + confirmation объект буцаана. Дуудагч ЯГ ижил биеийг confirmation_token-той дахин илгээнэ. Approval queue-д мөр ҮҮСГЭХГҮЙ — operator өөрөө шууд энд байна (спек A-8).

Authorizations:
operatorSession

required
string <uuid>

Клиент үүсгэнэ. Энэ утга нь client_order_id-ийн үндэс болно. Ижил key + ижил бие = ижил хариу, давхар order БАЙХГҮЙ. Ижил key + өөр бие = 409 idempotency_conflict.
